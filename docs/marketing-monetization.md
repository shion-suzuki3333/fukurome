# フクロメ — マーケティング & 収益化方針

前提: **低運用・非YMYL・端末内完結・概算ツール**。  
「問題を起こさない」= 誇大表現・ステマ・検索スパム・AdSense/景表法違反を避ける。

---

## 1. 誰に、何を届けるか

| 項目 | 内容 |
|------|------|
| 主ペルソナ | 一人暮らし〜ファミリーで、袋を買って「入らない」経験がある人 |
| ジョブ | 買い物前に、合わない袋を買わずに済ませたい |
| 約束 | 寸法を入れると 10–90L の目安が出る（概算・自治体指定袋優先） |
| 言わないこと | 「絶対に合う」「このメーカーが正解」「捨て方はこうすべき」 |

検索意図の核は **情報収集 + その場の判断**。比較・レビューより「測って決める」が差別化。

---

## 2. 検索で出やすくする（SEO）— 安全なやり方

### やる

1. **意図ごとのページを薄く増やしすぎない**
   - ツール本体（`/`）
   - 測り方（`/guide`）
   - 失敗パターン記事（`/articles/*`）
   - 免責・プライバシー（信頼）
2. **ロングテールを記事で拾う**（1ページ1意図）
   - 「ゴミ袋 サイズ 合わない」
   - 「ゴミ箱 何リットル」
   - 「45L 入らない」
   - 「丸型 ゴミ箱 袋」
   - 「ゴミ袋 測り方」
3. **タイトル・見出しは検索語に寄せつつ事実ベース**
   - ○「45Lなのに合わないときのチェックリスト」
   - ×「買うな！絶対失敗するゴミ袋ランキング」
4. **構造化データ**（実装済み: WebApplication / FAQPage）を維持
5. **内部リンク**
   - 記事 → `#checker` / `#results`
   - 結果まわり → 測り方・免責
6. **sitemap + `NEXT_PUBLIC_SITE_URL`** を本番で必ず設定
7. **表示速度・モバイル**を落とさない（広告は結果の後だけ）

### やらない（問題になりやすい）

| 禁止寄り | 理由 |
|----------|------|
| 同一文言の量産記事 | 薄いコンテンツ・ペナルティリスク |
| キーワード詰め込みタイトル | クリックは取れても直帰・信頼低下 |
| 他サイト文章の転載 | 著作権・品質 |
| クローキング / 隠しテキスト | ガイドライン違反 |
| 「公式」「推奨メーカー」を装う | 誤認・景表法リスク |
| 自治体ルールを断定更新 | 鮮度戦争・誤案内（YMYL隣接） |

### 公開後の最低運用（月1で足りる）

- Search Console 登録 → インデックス・クエリ確認
- 四半期で袋寸法表レビュー（`docs/ops.md`）
- 流入の多いクエリに対し、記事を **1本だけ** 追加（量より精度）

## 3. SNS — 何を、どう出すか

目的はフォロワー数ではなく **ツールへの短い導線** と **共有リンクの再利用**。

### 向いているチャネル

| チャネル | 使い方 | 頻度目安 |
|----------|--------|----------|
| **X** | 失敗談→測るコツ→結果リンク。画像は口まわり図解 | 週0〜2（無理しない） |
| **note** | 測り方・一人暮らしの買い物失敗を長文1本。末尾にフクロメ | 月0〜1 |
| **Yahoo!知恵袋 / 教えて!goo**（回答） | 既存質問に手順で回答し、補足としてツールリンク | 偶発 |
| **Instagram** | リールより静的図解（測り方3枚）。リンクはプロフィール | 任意 |

### 投稿の型（炎上・誤認を避ける）

1. **共感**（買った袋が入らなかった）
2. **事実1つ**（L表記だけでは口まわりが足りないことがある）
3. **行動**（内側を測る / ツールで目安）
4. **留保**（自治体指定袋・メーカー実寸を優先）

### SNSでやらない

- 特定メーカー・店のネガキャン
- 「これ以外買うな」断定
- 結果スクショに広告誘導文を重ねる
- 相互フォロー・ハッシュタグスパム
- 寸法データの収集を匂わせる（端末内完結の信頼を壊す）

### 共有を設計に乗せる（実装済みの強み）

- `?shape=&w=&d=&h=#results` の共有リンクを投稿に使う
- 「自分のゴミ箱で試して」と呼び、アプリ側は概算注記を維持

## 4. コミュニティ・他媒体（低リスク）

- **引越し・一人暮らし系のまとめ記事**に「測ってから買う」として自然言及（営業メールは控えめ・ステマ防止のPR表記）
- **自作の図解を CC ではなく自サイトホスト**で使い回し（帰属明確）
- 広告付きまとめサイトへの過度な相互リンクは避ける

---

## 5. 収益化 — 優先順位と境界線

低運用なら **本線は広告**、副線は **開示付きアフィリエイト**。混ぜ方を間違えると信頼も審査も落ちる。

### A. Google AdSense（本線・推奨）

| 項目 | 方針 |
|------|------|
| 置き場 | 結果の下 / 記事末尾 / FAQ〜フッター間のみ（`docs/adsense.md`） |
| 置かない | ヒーロー、入力中、判定ボタン直上・直下 |
| コピー | 「広告をクリック」禁止。結果の第一候補を広告に見せない |
| CSP | 本番で広告ドメインを最小追加 |
| 審査 | プライバシー・免責・実コンテンツ（記事）を揃えてから申請 |

想定: セッション短めのユーティリティなので **RPMは高くない**。流入を検索＋共有で増やし、結果到達後に1枠が現実的。

### B. アフィリエイト（副線・慎重）

| やり方 | OK条件 |
|--------|--------|
| 記事末尾に「袋を探すなら」程度の楽天/Amazon検索リンク | 第一候補ロジックと **視覚分離**。PR・アフィリエイト開示 |
| 「45Lの探し方」記事内の一般リンク | 特定SKUを「ツールが推奨」と書かない |

| やり方 | NG |
|--------|-----|
| 結果カード自体を商品リンク化 | 概算ツールが推薦エンジンに見える |
| 判定スコア順に商品を並べる | 誤認・ステマ・返品トラブル |

**ルール:** ツール結果 = サイズ目安 / アフィリエイト = 「買う場所の一例」。文言で必ず分ける。

### C. やらない（または後回し）

- サブスク（このツールに払う理由が弱い）
- リード獲得・個人情報販売（端末内完結と矛盾）
- 動画強制・インタースティシャル（AdSense違反・UX破壊）
- 自治体・分別の有料相談（YMYL・運用地獄）

### D. 収益の育て方（運用負荷順）

1. 検索で記事2〜5本が安定インデックス
2. AdSense 申請・結果下1枠
3. Search Console でクエリを見て記事追加
4. 必要なら記事末尾のみアフィリエイト（開示必須）
5. SNSは「書いた記事の告知」に限定して炎上面を減らす

---

## 6. コンプライアンス・炎上予防チェックリスト

公開・投稿の前に確認:

- [ ] 「絶対」「必ず合う」など断定がない
- [ ] 自治体指定袋・メーカー実寸の優先が書いてある
- [ ] アフィリエイトなら PR / 広告表記がある
- [ ] 個人の寸法を収集・保存していない（現状どおり）
- [ ] 他社ブランドを揶揄していない
- [ ] 広告が判定操作を邪魔していない
- [ ] 寸法表の `SPECS_REVIEWED_AT` が古すぎない（四半期）

---

## 7. 最初の90日アクション（カレンダー日数ではなく手順）

1. 本番ドメイン + `NEXT_PUBLIC_SITE_URL` + Search Console
2. 既存記事2本のタイトルをクエリに合わせて微調整
3. 「丸型ゴミ箱 袋」意図の記事を1本追加
4. AdSense 申請（ポリシーページ・コンテンツ充足を確認）
5. X か note で測り方図解を1本だけ固定・プロフィールにURL
6. 共有リンク付きの「キッチン中プリセット」デモを1投稿

成功指標（控えめ）:

- 検索からの結果到達（ツール利用）が増えている
- 広告は結果後のみ
- クレーム・誤認レポートが実質ゼロ
